# Open-Source Release Provenance

Prepared: 2026-09-16

## Public baseline

Sweet DAW's public repository was created from a reviewed source snapshot rather than by exposing a long-lived private development history.

The initial public source tree was intentionally imported as a fresh root commit so historical backup archives, experimental branches, local artifacts, and unrelated development history would not become part of the public distribution.

Initial public commit:

- message: `Initial open-source release`
- license: MIT
- release line: `0.1.x`

## Included content

The reviewed public baseline contains source code, documentation, tests, configuration, and generated application metadata.

It does not intentionally include:

- user WAV/stem files,
- commercial samples,
- external IR packs,
- ONNX or other model weights,
- third-party WASM DSP binaries,
- VST/AUv3 plug-in binaries,
- `.env` files or credentials,
- local backup/build archives,
- private Git development history.

## Licensing posture

- project license: MIT,
- built-in audio DSP: project-owned TypeScript/JavaScript and browser Web Audio APIs,
- direct runtime dependencies: documented in `THIRD_PARTY_NOTICES.md`,
- GPL/AGPL DAW/DSP implementations: not intentionally vendored or imported into the reviewed public core.

Any future introduction of copyleft DSP code, model weights, external IR/sample packs, native plug-in hosting, ffmpeg/Rubber Band WASM, or similar binary dependencies requires a new license/security/provenance review before release.

## Publication checks

Before the initial public release, the clean source snapshot was checked for common secret/key patterns and unwanted artifact types, and the following verification suite was run successfully:

```bash
npm ci
npm run typecheck
npm run test
npm run build
npm run aimix:selftest
```

The repository also includes a GitHub Actions workflow that repeats the core verification checks.

## Local-first security posture

Core Sweet DAW audio processing is designed to run in the browser. A future change that introduces remote audio upload, credential handling, analytics involving audio content, external models, or a remote audio-processing API must be explicitly documented and reviewed before release.

## Third-party service independence

Sweet DAW can process user-provided files generated by third-party music tools, but the project is independent and is not an official integration of those services. The reviewed local workflow does not require service credentials, account automation, or an unofficial service API client.

This document records engineering release provenance and does not replace the license terms of Sweet DAW or its dependencies.
