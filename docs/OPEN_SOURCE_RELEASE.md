# Open-Source Release Baseline

Prepared: 2026-09-16

## Source baseline

The open-source preparation branch was created from:

- repository: `drvfua-debug/sweet-daw`
- source branch: `codex/aimix-clip-intelligence`
- source commit: `5413440c7195d420dad2d97a8a19b575dd5197aa`
- source commit date: 2026-07-22

This source branch is newer than the current private `main` and contains the active AIMIX/mastering implementation used as the publication candidate.

## Publication model

Do **not** make the existing private development repository public as the release mechanism. The private repository contains unrelated historical branches and old build/backup artifacts that are not part of the reviewed publication snapshot.

Create the public repository from a clean snapshot of this preparation branch, without importing the private Git history. The first public commit should contain only the reviewed working tree.

## Included posture

The reviewed candidate contains source code, documentation, tests, configuration, and generated app metadata. It does not intentionally include:

- user WAV/stem files,
- commercial samples,
- external IR packs,
- ONNX or other model weights,
- third-party WASM DSP binaries,
- VST/AUv3 binaries,
- `.env` files or credentials,
- build ZIP archives.

## Licensing posture

- project license: MIT
- built-in audio DSP: project-owned TypeScript/JavaScript and browser Web Audio APIs
- direct runtime dependencies: permissive licenses documented in `THIRD_PARTY_NOTICES.md`
- GPL/AGPL DAW/DSP code: not intentionally vendored or imported in this snapshot

Any future introduction of GPL/AGPL code, model weights, external IR/sample packs, ffmpeg/Rubber Band WASM, native plug-in hosting, or marketplace-loaded DSP requires a new license/security review before release.

## Required pre-publication checks

1. Export only the working tree of `oss/public-release-prep`; do not copy private `.git` history.
2. Run a secret scan against the clean export.
3. Verify no ignored user audio or local backups are copied into the export.
4. Run `npm ci`, `npm run typecheck`, `npm run test`, `npm run build`, and `npm run aimix:selftest`.
5. Review `LICENSE`, `THIRD_PARTY_NOTICES.md`, `SECURITY.md`, and `CONTRIBUTING.md`.
6. Create the public repository from the clean export as a fresh initial commit.
7. Keep the public repository private until the final secret/license check passes; only then switch that new repository to public visibility.

## Trademark / service independence

Sweet DAW can process files generated by third-party tools including Suno, but the project is independent and is not an official Suno product or integration. No Suno credentials, unofficial API client, account automation, or service token is required by the reviewed browser-local workflow.
